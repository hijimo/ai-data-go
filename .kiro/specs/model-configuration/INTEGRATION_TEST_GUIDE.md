# 模型配置模块集成测试指南

## 概述

本文档描述了模型配置模块的集成测试策略和执行方法。由于项目中现有的集成测试框架存在编译问题，我们提供了手动测试脚本和详细的测试用例说明。

## 测试覆盖范围

根据任务要求，集成测试覆盖以下场景：

### 1. 创建模型配置测试

#### 1.1 租户管理员创建配置（自动使用当前租户）

- **测试目标**: 验证租户管理员可以在自己的租户下创建模型配置
- **预期结果**:
  - HTTP 201 Created
  - 返回的配置自动关联到当前租户
  - API密钥已脱敏（显示前4位和后4位，中间为****）

#### 1.2 平台管理员创建配置（指定租户ID）

- **测试目标**: 验证平台管理员可以为任意租户创建模型配置
- **预期结果**:
  - HTTP 201 Created
  - 配置关联到指定的租户ID
  - API密钥已脱敏

#### 1.3 租户管理员尝试跨租户创建（应失败）

- **测试目标**: 验证租户管理员无法在其他租户下创建配置
- **预期结果**:
  - HTTP 403 Forbidden
  - 错误消息："权限不足：只能在当前租户下创建模型配置"

### 2. 查询模型配置测试

#### 2.1 租户管理员查询自己租户的配置

- **测试目标**: 验证租户管理员可以查看自己租户的配置
- **预期结果**:
  - HTTP 200 OK
  - 返回配置详情
  - API密钥已脱敏

#### 2.2 租户管理员尝试访问其他租户配置（应返回403）

- **测试目标**: 验证租户管理员无法访问其他租户的配置
- **预期结果**:
  - HTTP 403 Forbidden
  - 错误消息："权限不足：无法访问其他租户的模型配置"

#### 2.3 平台管理员跨租户访问（应成功）

- **测试目标**: 验证平台管理员可以访问任意租户的配置
- **预期结果**:
  - HTTP 200 OK
  - 返回配置详情

### 3. 列表查询测试

#### 3.1 租户管理员查询配置列表

- **测试目标**: 验证租户管理员只能看到自己租户的配置
- **预期结果**:
  - HTTP 200 OK
  - 返回的配置列表只包含当前租户的配置
  - 支持分页参数

#### 3.2 平台管理员查询所有配置

- **测试目标**: 验证平台管理员可以查看所有租户的配置
- **预期结果**:
  - HTTP 200 OK
  - 返回所有租户的配置列表
  - 可以通过tenantId参数过滤特定租户

### 4. 更新模型配置测试

#### 4.1 租户管理员更新自己租户的配置

- **测试目标**: 验证租户管理员可以更新自己租户的配置
- **预期结果**:
  - HTTP 200 OK
  - 配置已更新
  - updated_at和updated_by字段已更新

#### 4.2 租户管理员尝试更新其他租户配置（应失败）

- **测试目标**: 验证租户管理员无法更新其他租户的配置
- **预期结果**:
  - HTTP 403 Forbidden

### 5. 启用/禁用功能测试

#### 5.1 禁用模型配置

- **测试目标**: 验证可以禁用模型配置
- **预期结果**:
  - HTTP 200 OK
  - is_enabled字段设置为false
  - 禁用后的配置不出现在可用列表中

#### 5.2 启用模型配置

- **测试目标**: 验证可以重新启用模型配置
- **预期结果**:
  - HTTP 200 OK
  - is_enabled字段设置为true
  - 启用后的配置出现在可用列表中

### 6. 软删除功能测试

#### 6.1 删除模型配置

- **测试目标**: 验证软删除功能正常工作
- **预期结果**:
  - HTTP 200 OK
  - is_deleted字段设置为true
  - deleted_at和deleted_by字段已设置
  - 删除后的配置无法通过API访问
  - 数据库中记录仍然存在

#### 6.2 租户管理员尝试删除其他租户配置（应失败）

- **测试目标**: 验证租户管理员无法删除其他租户的配置
- **预期结果**:
  - HTTP 403 Forbidden

### 7. 可用模型列表测试

#### 7.1 查询可用模型列表

- **测试目标**: 验证只返回已启用且未删除的配置
- **预期结果**:
  - HTTP 200 OK
  - 只返回is_enabled=true且is_deleted=false的配置
  - 不包含敏感信息（API密钥、查询参数等）
  - 只包含基本字段：id、name、model、modelProvider

### 8. 模型配置验证测试

#### 8.1 验证OpenAI配置

- **测试目标**: 验证OpenAI模型配置连接
- **预期结果**:
  - HTTP 200 OK
  - 返回验证结果（valid、message、details）
  - 验证超时时间为30秒

#### 8.2 验证其他提供商配置

- **测试目标**: 验证Anthropic、Google GenAI等提供商配置
- **预期结果**:
  - HTTP 200 OK
  - 返回相应的验证结果

#### 8.3 租户管理员尝试验证其他租户配置（应失败）

- **测试目标**: 验证租户管理员无法验证其他租户的配置
- **预期结果**:
  - HTTP 403 Forbidden

### 9. API密钥脱敏测试

#### 9.1 创建时脱敏

- **测试目标**: 验证创建配置时返回的API密钥已脱敏
- **预期结果**:
  - 返回的apiKey字段包含****
  - 只显示前4位和后4位

#### 9.2 查询时脱敏

- **测试目标**: 验证查询配置时返回的API密钥已脱敏
- **预期结果**:
  - 返回的apiKey字段包含****
  - 原始密钥不会泄露

#### 9.3 列表查询时脱敏

- **测试目标**: 验证列表查询时所有配置的API密钥已脱敏
- **预期结果**:
  - 所有配置的apiKey字段都已脱敏

### 10. 审计日志验证

#### 10.1 创建操作日志

- **测试目标**: 验证创建配置时记录审计日志
- **预期内容**:
  - event: model_config_created
  - user_id: 操作者ID
  - tenant_id: 租户ID
  - config_id: 配置ID
  - provider: 模型提供商

#### 10.2 更新操作日志

- **测试目标**: 验证更新配置时记录审计日志
- **预期内容**:
  - event: model_config_updated
  - 包含操作者和目标配置信息

#### 10.3 删除操作日志

- **测试目标**: 验证删除配置时记录审计日志
- **预期内容**:
  - event: model_config_deleted
  - 包含操作者和目标配置信息

#### 10.4 权限验证失败日志

- **测试目标**: 验证权限验证失败时记录审计日志
- **预期内容**:
  - event: permission_denied
  - reason: 失败原因
  - 包含用户和目标资源信息

### 11. 未认证访问测试

#### 11.1 所有接口未认证访问

- **测试目标**: 验证所有接口都需要认证
- **预期结果**:
  - HTTP 401 Unauthorized
  - 所有接口都返回未认证错误

### 12. 参数验证测试

#### 12.1 必填字段验证

- **测试目标**: 验证必填字段缺失时返回错误
- **预期结果**:
  - HTTP 422 Unprocessable Entity
  - 返回详细的验证错误信息

#### 12.2 字段格式验证

- **测试目标**: 验证字段格式不正确时返回错误
- **预期结果**:
  - HTTP 422 Unprocessable Entity
  - 返回格式错误信息

## 测试执行方法

### 方法1: 使用手动测试脚本

```bash
# 1. 启动服务器
make run

# 2. 获取测试Token（通过登录API）
# 租户1管理员Token
export TENANT1_ADMIN_TOKEN="your_tenant1_admin_token"

# 租户2管理员Token
export TENANT2_ADMIN_TOKEN="your_tenant2_admin_token"

# 平台管理员Token
export SYSTEM_ADMIN_TOKEN="your_system_admin_token"

# 3. 运行测试脚本
./test/integration/model_configuration_manual_test.sh
```

### 方法2: 使用curl手动测试

详细的curl命令示例请参考测试脚本内容。

### 方法3: 使用Postman/Insomnia

1. 导入API文档（Swagger）
2. 配置环境变量（Token、Base URL）
3. 按照测试用例逐个执行

## 测试数据准备

### 创建测试租户

```bash
# 使用平台管理员Token创建测试租户
curl -X POST http://localhost:8080/api/v1/tenants \
  -H "Authorization: Bearer $SYSTEM_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "测试租户1",
    "domain": "test1.example.com"
  }'
```

## 测试结果验证

### 数据库验证

```sql
-- 查看创建的配置
SELECT * FROM model_configurations WHERE is_deleted = false;

-- 查看软删除的配置
SELECT * FROM model_configurations WHERE is_deleted = true;

-- 验证API密钥已加密
SELECT id, name, LEFT(api_key, 20) as encrypted_key FROM model_configurations;

-- 查看审计日志
SELECT * FROM auth_audit WHERE event LIKE 'model_config%' ORDER BY created_at DESC LIMIT 10;
```

### 日志验证

```bash
# 查看应用日志
tail -f logs/app-$(date +%Y-%m-%d).log | grep "model_config"

# 查看权限验证失败日志
tail -f logs/app-$(date +%Y-%m-%d).log | grep "permission_denied"
```

## 已知问题

1. **现有集成测试框架问题**: 项目中的 `test/integration/*_test.go` 文件存在编译错误，需要修复后才能使用Go测试框架。

2. **Token获取**: 手动测试需要先通过登录API获取有效的JWT Token。

3. **真实API验证**: 模型配置验证功能需要真实的API密钥才能完全测试，测试环境中可能会失败。
