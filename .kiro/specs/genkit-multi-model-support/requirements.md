# 需求文档：Genkit 多模型支持

## 功能概述

扩展现有的 Genkit AI 服务，支持多个大模型提供商，包括 Google AI (Gemini)、Azure OpenAI 和阿里云百炼，所有模型统一通过 Google Genkit 框架进行调用。

## 用户故事

### 故事 1：配置多个模型提供商

**作为** 租户管理员  
**我希望** 能够通过 model_configuration 表为租户配置多个 AI 模型（Google AI、Azure OpenAI、百炼）  
**以便** 租户可以根据需求使用不同的模型服务

**验收标准**：

- 当租户在 model_configuration 表中配置了多个模型时，系统应该能够根据租户ID和模型名称查询到对应配置
- 当租户请求使用某个模型时，系统应该通过租户ID和模型名称获取该模型的配置信息
- 当模型配置缺少必需字段时，系统应该返回明确的错误信息
- 当租户请求不存在的模型配置时，系统应该返回友好的错误提示

### 故事 2：使用 Azure OpenAI 模型

**作为** API 用户  
**我希望** 能够通过 Genkit 框架调用 Azure OpenAI 的模型（如 GPT-4）  
**以便** 利用 Azure 的企业级服务和数据隐私保护

**验收标准**：

- 当用户发送消息到配置为 Azure OpenAI 的会话时，系统应该调用 Azure OpenAI API
- 当 Azure OpenAI 返回响应时，系统应该正确解析并返回给用户
- 当使用流式接口时，系统应该实时返回 Azure OpenAI 的流式响应
- 当 Azure OpenAI 调用失败时，系统应该返回友好的错误信息

### 故事 3：使用阿里云百炼模型

**作为** API 用户  
**我希望** 能够通过 Genkit 框架调用阿里云百炼的模型（如 Qwen）  
**以便** 使用国内的大模型服务，获得更好的中文理解能力

**验收标准**：

- 当用户发送消息到配置为百炼的会话时，系统应该调用百炼 API
- 当百炼返回响应时，系统应该正确解析并返回给用户
- 当使用流式接口时，系统应该实时返回百炼的流式响应
- 当百炼调用失败时，系统应该返回友好的错误信息

### 故事 4：动态选择模型提供商

**作为** API 用户  
**我希望** 能够在发送消息时指定使用哪个模型提供商  
**以便** 根据不同的场景选择最合适的模型

**验收标准**：

- 当请求中指定了提供商名称时，系统应该使用指定的提供商
- 当请求中未指定提供商时，系统应该使用默认提供商
- 当请求中指定了不存在的提供商时，系统应该返回错误信息
- 当切换提供商时，系统应该保持会话上下文的独立性

### 故事 5：保持向后兼容

**作为** 现有系统用户  
**我希望** 新的多模型支持不影响现有的 Google AI (Gemini) 功能  
**以便** 平滑升级系统而不影响现有业务

**验收标准**：

- 当使用现有的 API 接口时，系统应该继续正常工作
- 当未配置新的提供商时，系统应该默认使用 Google AI
- 当现有配置文件未更新时，系统应该能够正常启动
- 当调用现有的流式接口时，响应格式应该保持不变

## 功能需求

### FR-1: 配置管理

- 系统必须支持从 model_configuration 表读取模型配置
- 系统必须通过租户ID和模型名称查询模型配置
- 每个模型配置必须包含：提供商类型、API 密钥、模型名称
- Azure OpenAI 配置必须额外包含：Endpoint、Deployment、API Version
- 百炼配置必须额外包含：Endpoint、Workspace
- 系统必须支持配置信息的加密存储

### FR-2: Genkit 客户端扩展

- Genkit 客户端必须支持初始化不同类型的插件
- 客户端必须能够根据配置动态选择插件
- 客户端必须支持 Google AI、Azure OpenAI、百炼三种插件
- 客户端接口必须保持不变，确保向后兼容

### FR-3: 插件实现

- 必须实现或集成 Google AI 插件（已存在）
- 必须实现或集成 Azure OpenAI 插件
- 必须实现或集成百炼插件（可能需要自定义）
- 所有插件必须支持流式和非流式两种调用方式

### FR-4: 模型选择机制

- API 请求必须支持通过参数指定模型名称
- 系统必须根据当前租户ID和请求的模型名称查询 model_configuration 表
- 当租户未配置请求的模型时，系统必须返回明确的错误信息
- 系统必须验证查询到的模型配置是否完整有效

### FR-5: 错误处理

- 当提供商配置错误时，必须返回明确的错误信息
- 当 API 调用失败时，必须记录详细的错误日志
- 当模型不可用时，必须返回友好的错误提示
- 错误信息必须包含足够的上下文用于排查问题

## 非功能需求

### NFR-1: 性能

- 切换模型提供商不应增加超过 50ms 的延迟
- 流式响应的首字节时间不应超过 2 秒
- 系统应该能够并发处理至少 100 个请求

### NFR-2: 可维护性

- 代码必须遵循现有的项目结构和命名规范
- 新增代码必须包含完整的注释
- 必须提供配置示例和使用文档
- 插件实现必须模块化，便于后续扩展

### NFR-3: 安全性

- API 密钥必须通过环境变量或加密配置管理
- 日志中不得包含 API 密钥等敏感信息
- 必须验证所有外部输入参数
- 必须遵循多租户访问控制规范

### NFR-4: 可观测性

- 必须记录每次模型调用的提供商、模型、耗时
- 必须记录 Token 使用情况
- 必须记录所有错误和异常
- 日志必须包含 TraceID 用于链路追踪

## 约束条件

### 技术约束

- 必须使用 Google Genkit 框架作为统一的 AI 调用层
- 必须保持现有的 API 接口不变
- 必须使用 Go 语言实现
- 必须兼容现有的数据库结构

### 业务约束

- 不得影响现有用户的使用
- 必须在 2 周内完成开发和测试
- 必须提供完整的迁移文档

### 依赖约束

- 依赖 Google Genkit Go SDK
- 可能依赖 Azure OpenAI Go SDK
- 可能依赖阿里云百炼 Go SDK
- 依赖现有的配置管理系统

## 优先级

### P0 (必须实现)

- 配置管理功能
- Genkit 客户端扩展
- Azure OpenAI 插件集成
- 基本的错误处理

### P1 (应该实现)

- 百炼插件集成
- 动态模型选择
- 完整的错误处理和日志
- 性能优化

### P2 (可以实现)

- 模型切换的监控指标
- 自动故障转移
- 模型响应缓存
- 成本统计

## 验收测试场景

### 场景 1: 配置查询测试

1. 在 model_configuration 表中为测试租户配置三个模型
2. 通过租户ID和模型名称查询配置
3. 验证能够正确查询到所有模型配置
4. 验证配置信息完整准确

### 场景 2: Azure OpenAI 调用测试

1. 配置 Azure OpenAI 提供商
2. 发送测试消息
3. 验证调用 Azure OpenAI API
4. 验证响应格式正确
5. 验证 Token 统计准确

### 场景 3: 百炼调用测试

1. 配置百炼提供商
2. 发送测试消息
3. 验证调用百炼 API
4. 验证响应格式正确
5. 验证中文处理正确

### 场景 4: 流式响应测试

1. 配置任意提供商
2. 发送流式请求
3. 验证实时返回响应块
4. 验证最终响应完整
5. 验证 SSE 格式正确

### 场景 5: 错误处理测试

1. 配置错误的 API 密钥
2. 发送测试消息
3. 验证返回友好的错误信息
4. 验证错误日志记录完整
5. 验证系统不崩溃

### 场景 6: 向后兼容测试

1. 使用现有的 API 接口
2. 不指定提供商参数
3. 验证使用默认提供商
4. 验证响应格式不变
5. 验证功能正常

## 术语表

- **Genkit**: Google 开发的 AI 应用开发框架
- **Provider**: 模型提供商，如 Google AI、Azure OpenAI、百炼
- **Plugin**: Genkit 插件，用于集成不同的模型提供商
- **Deployment**: Azure OpenAI 中的模型部署实例
- **Workspace**: 百炼中的工作空间概念
- **SSE**: Server-Sent Events，服务器推送事件，用于流式响应
