# 平台管理员租户系统需求文档

## 简介

本文档定义了多租户系统中"平台管理员租户"（Platform Admin Tenant）的需求。该系统解决了多租户系统初始化时的循环依赖问题：创建用户需要租户，但创建租户又需要用户权限。通过引入系统级管理员公司和平台管理员账户，实现系统的自举（bootstrap）和租户生命周期管理。

## 术语表

- **系统**：平台管理员租户系统
- **平台租户（Platform Tenant）**：系统级特殊租户，类型为 "system"，用于承载平台管理员
- **平台管理员（Platform Admin）**：隶属于平台租户的系统管理员，拥有跨租户管理权限
- **业务租户（Business Tenant）**：普通租户，类型为 "tenant"，用于实际业务使用
- **租户管理员（Tenant Admin）**：业务租户的管理员，仅拥有本租户内的管理权限
- **租户用户（Tenant User）**：业务租户的普通用户，拥有基本业务权限
- **系统初始化（System Bootstrap）**：系统首次启动时自动创建平台租户和平台管理员的过程
- **租户自动管理员（Auto Tenant Admin）**：创建租户时自动生成的租户管理员账户

## 需求

### 需求 1：平台租户初始化

**用户故事：** 作为系统部署人员，我希望系统首次启动时能够自动创建平台租户和平台管理员，以便能够开始管理整个系统

#### 验收标准

1. 当系统首次启动时，系统应该检查是否存在类型为 "system" 的租户
2. 当不存在平台租户时，系统应该创建一个名为 "Platform" 的租户，类型设置为 "system"，域名设置为 "system.local"
3. 当平台租户创建成功时，系统应该创建一个平台管理员用户，邮箱为配置文件中指定的值（默认 "<admin@system.local>"），密码为配置文件中指定的值
4. 当平台管理员创建成功时，系统应该将其角色设置为 ["system_admin"]，is_admin 字段设置为 true
5. 当平台租户和管理员已存在时，系统应该跳过初始化过程并记录日志

### 需求 2：租户类型区分

**用户故事：** 作为系统架构师，我希望能够区分平台租户和业务租户，以便实现不同的权限控制和业务逻辑

#### 验收标准

1. 当创建租户时，系统应该允许指定租户类型为 "system" 或 "tenant"
2. 当租户类型为 "system" 时，系统应该限制只能有一个平台租户存在
3. 当租户类型为 "tenant" 时，系统应该允许创建多个业务租户
4. 当查询租户时，系统应该能够根据类型过滤租户列表
5. 当删除平台租户时，系统应该拒绝操作并返回错误

### 需求 3：角色层次结构

**用户故事：** 作为系统管理员，我希望系统能够支持不同层次的角色，以便实现分级权限管理

#### 验收标准

1. 系统应该支持 "system_admin" 角色，该角色拥有所有租户的管理权限
2. 系统应该支持 "tenant_admin" 角色，该角色仅拥有所属租户内的管理权限
3. 系统应该支持 "user" 角色，该角色仅拥有基本业务权限
4. 当用户拥有 "system_admin" 角色时，系统应该允许其访问所有租户的数据和管理接口
5. 当用户拥有 "tenant_admin" 角色时，系统应该仅允许其访问所属租户的数据和管理接口

### 需求 4：平台管理员权限

**用户故事：** 作为平台管理员，我希望能够管理所有租户的生命周期，以便维护整个系统的正常运行

#### 验收标准

1. 当平台管理员创建租户时，系统应该允许创建类型为 "tenant" 的业务租户
2. 当平台管理员查询租户列表时，系统应该返回所有租户（包括平台租户和业务租户）
3. 当平台管理员禁用租户时，系统应该将租户状态设置为禁用，并阻止该租户下所有用户的访问
4. 当平台管理员启用租户时，系统应该将租户状态设置为启用，并恢复该租户下用户的访问
5. 当平台管理员删除业务租户时，系统应该执行软删除操作，标记租户为已删除状态

### 需求 5：租户创建时自动生成管理员

**用户故事：** 作为平台管理员，我希望在创建业务租户时能够自动生成租户管理员账户，以便租户可以立即开始使用系统

#### 验收标准

1. 当平台管理员创建业务租户时，系统应该自动为该租户创建一个租户管理员账户
2. 当自动创建租户管理员时，系统应该生成邮箱格式为 "admin@{tenant_domain}" 或使用请求中提供的邮箱
3. 当自动创建租户管理员时，系统应该生成随机密码（至少 16 字符，包含大小写字母、数字和特殊字符）
4. 当租户管理员创建成功时，系统应该将其角色设置为 ["tenant_admin"]，is_admin 字段设置为 true
5. 当租户管理员创建成功时，系统应该返回管理员的邮箱和初始密码给平台管理员

### 需求 6：租户管理员权限

**用户故事：** 作为租户管理员，我希望能够管理本租户内的用户，以便控制谁可以访问我们的数据

#### 验收标准

1. 当租户管理员创建用户时，系统应该验证用户邮箱在该租户内的唯一性
2. 当租户管理员查询用户列表时，系统应该仅返回该租户下的用户信息
3. 当租户管理员更新用户信息时，系统应该验证用户属于该租户，并允许更新
4. 当租户管理员禁用用户时，系统应该将用户状态设置为非活跃，并撤销该用户的所有有效 Token
5. 当租户管理员尝试访问其他租户的数据时，系统应该拒绝请求并返回权限错误

### 需求 7：权限验证中间件

**用户故事：** 作为 API 开发者，我希望有统一的权限验证中间件，以便简化不同角色的权限控制

#### 验收标准

1. 当 API 请求需要平台管理员权限时，系统应该验证用户角色包含 "system_admin"
2. 当 API 请求需要租户管理员权限时，系统应该验证用户角色包含 "tenant_admin" 或 "system_admin"
3. 当 API 请求需要访问特定租户数据时，系统应该验证用户属于该租户或拥有 "system_admin" 角色
4. 当用户权限不足时，系统应该返回 403 禁止访问错误
5. 当用户未认证时，系统应该返回 401 未授权错误

### 需求 8：平台管理员登录

**用户故事：** 作为平台管理员，我希望能够使用特殊的登录方式访问系统，以便管理所有租户

#### 验收标准

1. 当平台管理员登录时，系统应该识别其所属租户为平台租户（类型为 "system"）
2. 当平台管理员登录成功时，系统应该在 JWT Token 中包含 "system_admin" 角色
3. 当平台管理员登录成功时，系统应该在 JWT Token 中包含平台租户的 tenant_id
4. 当平台管理员使用 Token 访问 API 时，系统应该允许其跨租户访问数据
5. 当平台管理员注销时，系统应该撤销其 Refresh Token

### 需求 9：租户状态管理

**用户故事：** 作为平台管理员，我希望能够控制租户的启用和禁用状态，以便管理租户的访问权限

#### 验收标准

1. 当平台管理员禁用租户时，系统应该将租户的 status 字段设置为 false
2. 当租户被禁用时，系统应该拒绝该租户下所有用户的登录请求
3. 当租户被禁用时，系统应该拒绝该租户下所有用户的 API 访问请求
4. 当平台管理员启用租户时，系统应该将租户的 status 字段设置为 true
5. 当租户被启用时，系统应该恢复该租户下用户的正常访问

### 需求 10：初始化配置

**用户故事：** 作为系统部署人员，我希望能够通过配置文件自定义平台管理员的初始信息，以便满足不同的部署需求

#### 验收标准

1. 系统应该支持通过环境变量配置平台管理员的邮箱（PLATFORM_ADMIN_EMAIL）
2. 系统应该支持通过环境变量配置平台管理员的初始密码（PLATFORM_ADMIN_PASSWORD）
3. 系统应该支持通过环境变量配置平台管理员的显示名称（PLATFORM_ADMIN_NAME）
4. 当环境变量未设置时，系统应该使用默认值（邮箱：<admin@system.local>，密码：随机生成，名称：Platform Admin）
5. 当系统初始化完成时，系统应该在日志中记录平台管理员的邮箱和初始密码

### 需求 11：数据库表结构扩展

**用户故事：** 作为数据库管理员，我希望租户表能够支持租户类型字段，以便区分平台租户和业务租户

#### 验收标准

1. 系统应该在 tenants 表中添加 type 字段，类型为 VARCHAR(32)，默认值为 "tenant"
2. 系统应该在 tenants 表的 type 字段上创建索引
3. 系统应该在 tenants 表上创建唯一约束，确保只能有一个类型为 "system" 的租户
4. 系统应该在 users 表中保留 is_admin 字段，用于标识租户管理员
5. 系统应该在 users 表的 roles 字段中支持存储 ["system_admin", "tenant_admin", "user"] 等角色

### 需求 12：审计日志记录

**用户故事：** 作为安全审计员，我希望系统能够记录所有平台管理员的操作，以便进行安全审计和问题追踪

#### 验收标准

1. 当平台管理员创建租户时，系统应该记录审计日志，包含操作类型、租户 ID、操作者 ID 和时间戳
2. 当平台管理员禁用或启用租户时，系统应该记录审计日志
3. 当平台管理员删除租户时，系统应该记录审计日志
4. 当租户管理员创建用户时，系统应该记录审计日志
5. 当租户管理员禁用或删除用户时，系统应该记录审计日志
