# 并发性能测试快速参考

## 概述

并发性能测试用于验证 Genkit 多模型支持在并发负载下的性能表现。

## 测试场景

### 1. 低并发测试（10个并发）

- **目的**: 验证系统在低负载下的基本性能
- **并发数**: 10
- **预期**: 所有请求成功，平均延迟 < 10秒

### 2. 中等并发测试（50个并发）

- **目的**: 验证系统在中等负载下的性能
- **并发数**: 50
- **预期**: 成功率 ≥ 95%，平均延迟 < 15秒

### 3. 高并发测试（100个并发）

- **目的**: 验证系统能够处理至少100个并发请求
- **并发数**: 100
- **预期**: 成功率 ≥ 90%，平均延迟 < 20秒

### 4. 并发流式调用测试（20个并发）

- **目的**: 验证流式调用的并发性能
- **并发数**: 20
- **预期**: 所有请求成功，平均 TTFB < 5秒

### 5. 混合并发测试（多提供商）

- **目的**: 验证多提供商并发调用的性能
- **并发数**: 50
- **预期**: 成功率 ≥ 90%

## 测试指标

### 性能指标

- **成功率**: 成功请求数 / 总请求数
- **吞吐量**: 成功请求数 / 总耗时（请求/秒）
- **平均延迟**: 所有成功请求的平均响应时间
- **最小/最大延迟**: 最快和最慢的请求响应时间
- **中位数延迟**: 50% 的请求响应时间
- **标准差**: 延迟的离散程度

### 流式调用指标

- **TTFB (Time To First Byte)**: 从发起请求到收到第一个数据块的时间
- **总时间**: 从发起请求到接收完所有数据的时间
- **数据块数量**: 流式响应的数据块总数

## 故障排查

### 问题 1: 高失败率

**症状**: 成功率低于预期

**可能原因**:

- API 密钥配额不足
- 网络连接不稳定
- 提供商 API 限流

**解决方案**:

1. 检查 API 密钥配额
2. 检查网络连接
3. 降低并发数重试
4. 检查提供商 API 状态

### 问题 2: 延迟过高

**症状**: 平均延迟超过预期

**可能原因**:

- 网络延迟高
- 提供商 API 响应慢
- 系统资源不足

**解决方案**:

1. 检查网络延迟
2. 尝试不同的提供商
3. 检查系统资源使用情况
4. 优化请求参数（如减少 maxTokens）

### 问题 3: 测试超时

**症状**: 测试运行超过 30 分钟

**可能原因**:

- 并发数过高
- API 响应极慢
- 死锁或资源泄漏

**解决方案**:

1. 降低并发数
2. 增加超时时间：`-timeout 60m`
3. 检查日志查找异常
4. 分批运行测试

## 性能优化建议

### 1. 连接池优化

- 确保 HTTP 客户端使用连接池
- 调整连接池大小以匹配并发数
- 设置合理的连接超时

### 2. 缓存优化

- 缓存 Genkit 实例（已实现）
- 缓存模型配置（已实现）
- 考虑缓存常见请求的响应

### 3. 资源管理

- 及时关闭不再使用的连接
- 使用 context 控制请求生命周期
- 监控内存使用情况

### 4. 并发控制

- 使用信号量限制并发数
- 实现请求队列
- 添加熔断器保护

## 注意事项

1. **API 配额**: 并发测试会消耗大量 API 配额，请确保有足够的配额
2. **测试时间**: 高并发测试可能需要较长时间，建议使用 `-timeout` 参数
3. **网络环境**: 测试结果受网络环境影响，建议在稳定的网络环境下运行
4. **资源清理**: 测试会自动清理创建的测试数据，无需手动清理
5. **并发限制**: 某些提供商可能有并发限制，请参考其文档
